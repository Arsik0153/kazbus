# Отчёт о подключении функционала Jol

Работа ведётся в отдельных ветках frontend и backend. Основные PR, в которых
собраны совместимые изменения:

- [Frontend #76](https://github.com/Arsik0153/kazbus/pull/76).
- [Backend #11](https://github.com/Arsik0153/jol_backend/pull/11).

Отдельные PR сохраняют небольшие части для review. Их не требуется вручную
собирать поверх общих веток. Часть frontend PR уже включена в интеграционную
ветку; это не слияние в `main` и не deployment.

## Подключённые сценарии

### Пассажир

- Поиск и направления используют реальные города, даты и доступность; фильтры и
  сортировка работают с данными API.
- История билетов показывает действующие статусы и сроки брони. Старые ссылки
  возврата направляют в историю вместо фиктивного успешного возврата.
- Сохранённых пассажиров можно добавлять, редактировать и удалять. Пассажир с
  историей билетов защищён от изменения/удаления, чтобы не переписывать прошлые
  поездки. Профильная запись ведёт в личные данные, а не в обычную форму пассажира.
- Старый endpoint заполнения профиля приведён к тем же ограничениям, чтобы через
  него нельзя было обойти защиту истории.
- Поддержка по собственному билету: создание обращения, переписка с перевозчиком,
  статусы и закрытие. Чужие билеты и чужие обращения недоступны.
- FAQ содержит открывающиеся ответы и ссылки на реальные разделы вместо `#`.
- Экран удаления аккаунта явно сообщает, что операция ещё не поддерживается;
  выход из сессии больше не выдаётся за удаление данных.

### Автобусный водитель

- Реальные рейсы, список пассажиров, история и транспорт.
- Подписанный QR, камера и ручной ввод; посадка проверяет принадлежность рейсу и
  оплату билета. Произвольная строка или чужой билет не подтверждает посадку.
- Изменение статуса рейса и создание обращения с сохранением на backend.

### Автобусная компания

- Ведомость пассажиров и CSV, мониторинг сохранённых статусов, показатели рейсов,
  бронирований, пассажиров и обращений.
- Обработка водительских обращений с безопасным повторным закрытием, в том числе
  при конкурентных запросах.
- Профиль компании загружается и сохраняется; PATCH отправляет изменённые поля.
- Регистрация нового перевозчика: отдельный подтверждённый номер, пароль,
  реквизиты и уникальный БИН/ИИН. Создаётся новый владелец без superuser-прав;
  существующий пассажирский аккаунт не повышает права через регистрацию.
- Реестр документов автобуса: свидетельство регистрации, страховка и техосмотр,
  даты окончания, загрузка/замена/скачивание/удаление. Статус отражает сохранённую
  дату, а не юридическую проверку документа.
- Двухэтажная схема сохраняет этаж места при создании, редактировании и бронировании.
  Старые места получают этаж 1; историческую потерянную разметку миграция не угадывает.
- Общий кабинет и документы адаптированы для узкого экрана.

### Cargo

- Рабочие кабинеты клиента, перевозчика и водителя; отдельная регистрация компаний
  и клиентов, одноразовые приглашения водителей.
- Запрос и подтверждение связи клиента с компанией, создание заказа, предложение
  условий и доплат, согласование, назначение транспорта и водителя.
- Последовательные этапы исполнения до доставки и история изменений.
- Запрет пересекающихся незавершённых назначений водителя или машины по датам
  загрузки и доставки; повтор того же назначения не создаёт дубликат.
- Поставки по дням недели/месяца, паузы и пропуски дат; запуск выполняется
  вручную либо автоматически при явном включении пользователем и оператором.
  Команда планировщика по умолчанию выполняет dry-run; она учитывает паузы,
  пропуски, активность сторон и расписание. Одна дата не создаёт повторные заказы
  при повторе или конкуренции.
- Склад и доступный остаток, атомарный резерв, освобождение при отмене и
  однократное списание после завершения рейса.
- Приватные документы заказов, подтверждений доставки и водителей с проверкой
  доступа по ролям и компании.

## Доступ, файлы и надёжность

- Автобусы, маршруты и водители привязаны к владельцу. Для старых записей есть
  аудит и явное назначение владельцев; автоматического захвата чужих записей нет.
- Общий каталог городов изменяет только администратор платформы. Перевозчик
  сохраняет возможность создавать свой маршрут с городами через соответствующий
  API.
- Удалён универсальный SMS-код. Код одноразовый, действует пять минут, допускает
  ограниченное число попыток. Сбой SMS-провайдера не создаёт рабочий код.
- Добавлены дневные бюджеты SMS по телефону, IP и всему приложению. Запрос,
  отклонённый до отправки, не расходует чужой бюджет.
- Передача клиентского IP через proxy включается явно и требует доверенной
  цепочки ingress → Next.js → Django; произвольному заголовку прямого клиента
  backend не доверяет.
- PDF/JPEG/PNG документов проверяются по содержимому и размеру, хранятся вне
  публичного MEDIA, скачиваются как приватное вложение. Замена и удаление файлов
  используют очередь очистки и повторную сверку после сбоев.
- Публичное изображение схемы автобуса ограничено по формату/размеру/разрешению и
  повторно кодируется под случайным именем.
- Токены frontend находятся в подписанных HttpOnly cookies. Для файловых
  изменений проверяется Origin; API дополнительно проверяет владельца объекта.
- Обновлены Next.js/React и Django, зафиксированы зависимости, восстановлены
  воспроизводимая установка и GitHub Actions. `npm audit` и `pip-audit` не нашли
  известных уязвимостей в проверенных наборах зависимостей.

## Что проверено

Итоговый локальный прогон: **209 backend-тестов** и
**39 frontend-тестов**, TypeScript, ESLint и production build. Проверен объединённый код последних изменений.

Браузерные проверки выполнялись с настоящим API на отдельных тестовых базах:
пассажиры/история/фильтры, водитель/QR/посадка, CSV, обращения диспетчера, профиль
компании, три роли Cargo, документы и их права доступа. Проверялись сохранение
после перезагрузки, ошибки API/сети, повторные действия и ширина экрана 390 px.

Регистрация проверена с локально подменённым SMS-провайдером: ошибка отправки,
повтор, неверный код, успешное создание, HttpOnly-сессия, сохранённый профиль,
безопасное поведение до JavaScript и разные IP-бюджеты за proxy. Реальные платные
SMS не отправлялись.

## Что нужно для запуска

1. Проверить и принять общие frontend/backend PR совместно.
2. Подготовить резервную копию базы и приватных файлов, проверить миграции на копии.
3. Назначить владельцев старым автобусам/маршрутам/водителям по dry-run отчёту из
   `OWNERSHIP_MIGRATION.md` backend.
4. Настроить общий Redis, секреты, HTTPS, hosts и новую учётную запись SMS-провайдера.
   Старые опубликованные ключи нужно отозвать: удаления из текущего кода недостаточно.
5. Настроить закрытые постоянные `CARGO_PRIVATE_ROOT` и `BUS_PRIVATE_ROOT`, лимит
   загрузки на proxy, backup и периодическую очистку файлов по `RUNTIME.md`.
6. При передаче IP включить согласованные настройки frontend/backend и закрыть
   прямой доступ к Next.js. Пример ingress приведён в документации backend.
7. Проверить реальную отправку SMS уже в настроенном окружении.

Исходная рабочая база не изменялась. Production не разворачивался, `main` не
обновлялся. Изменения доступны для review в GitHub.

## Оставшиеся границы

- Платёжная интеграция исключена по запросу. Оплата/денежный возврат не заявлены
  готовыми; тестовая посадка использовала подготовленные оплаченные билеты.
- GPS/телематика не подключены; мониторинг использует сохранённые статусы.
- Команда автоматических поставок реализована, но cron/timer в production не
  настраивался. До настройки и явного включения сохраняется ручной режим.
- Удаление/анонимизация аккаунта пассажира не реализованы.
- Проверка юридических реквизитов, антивирусная проверка документов и внешний
  production-мониторинг не выдаются за выполненные функции.

## Завершение по запросу пользователя

Работа остановлена досрочно по прямому запросу; достижения 50% квоты не ожидали.
Последними добавлены двухэтажные места, пассажирская поддержка и автоматические
поставки. Поддержка прошла реальный браузерный сценарий. Для двухэтажных мест и
автопоставок выполнены проверки кода/API, но их окончательные сквозные браузерные
прогоны отменены при остановке. Эти два сценария следует проверить перед выпуском.
Рабочее окружение и реальный SMS-провайдер не заменяют локальные тесты.

Последняя проверка квоты Codex перед завершением: **68% осталось**. Бесплатные
сбросы лимита не использовались. CI финальной отправки запускается на GitHub;
его завершения после просьбы остановиться не ожидали.
