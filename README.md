# Jol: пассажирские и грузовые перевозки

Frontend на Next.js 15 и React 19. Требуются Node.js 22, npm 10 и запущенный
`jol_backend` с изменениями Sapar, Cargo и операционного кабинета.

## Локальный запуск

```sh
cp .env.example .env.local
npm ci
npm run dev
```

В `.env.local` задайте `API_URL` с окончанием `/api_jol` и собственный случайный
`SESSION_SECRET`. API вызывается серверной частью Next.js; токены сессий не нужно
передавать в клиентский JavaScript. Для production нужны HTTPS и постоянный
`SESSION_SECRET`, одинаковый для всех экземпляров frontend.

Подготовка базы, Redis, SMS и принадлежности старых автобусов/маршрутов описана в
`RUNTIME.md` и `OWNERSHIP_MIGRATION.md` репозитория backend. Не присваивайте старые
записи перевозчику автоматически: сначала проверьте отчёт аудита и явный манифест.

## Кабинеты

| Адрес | Возможности |
| --- | --- |
| `/bus/main` | Поиск рейсов, фильтры, бронирование и история билетов |
| `/bus/support` | Обращения по собственным билетам и переписка с перевозчиком |
| `/busdriver` | Рейсы водителя, пассажиры, подписанный QR, посадка, статусы и обращения |
| `/admin/registration` | Регистрация автобусной компании с подтверждением телефона по SMS |
| `/admin/main` | Управление перевозками, ведомость и CSV, мониторинг, операционная аналитика, обработка обращений |
| `/shipper` | Компании, согласование перевозки, заказы, приватные документы, поставки, склад, профиль |
| `/admin-cargo` | Компания, клиенты, предложения и доплаты, водители, транспорт, назначения и склад |
| `/cargo` | Назначенные грузовые рейсы, этапы исполнения, подтверждение доставки и личные документы |

Cargo-клиент и перевозчик регистрируются отдельно. Водитель регистрируется по
одноразовому приглашению своей компании. До создания заказа клиент запрашивает
связь с компанией, а перевозчик подтверждает её. Затем перевозчик предлагает
условия, клиент принимает их, перевозчик назначает водителя и транспорт.

Поставки сохраняют расписание, паузы и пропущенные даты. Ручной запуск доступен
всегда; автоматический включается пользователем после настройки планировщика
оператором (`CARGO_SUPPLY_SCHEDULER_ENABLED`, `run_cargo_supplies --apply` на backend). Складские заказы резервируют доступный остаток на backend, отмена
освобождает резерв, завершение рейса списывает его один раз.

## SMS за reverse proxy

По умолчанию Django ограничивает отправку SMS по адресу непосредственного клиента.
Если Next.js вызывает API за пользователей, настройте доверенную цепочку, чтобы
разные посетители не делили один IP-лимит: ingress должен **перезаписывать**
`X-Real-IP` настоящим адресом клиента, а прямой доступ к Next.js должен быть закрыт.
Только при этих условиях включите `TRUST_PROXY_CLIENT_IP=true` на frontend и задайте
`TRUSTED_PROXY_IPS` на backend адресом Next.js. Frontend передаёт один проверенный
IP в `X-Forwarded-For`; произвольную цепочку из браузера он не пересылает.
Пример nginx и дневные SMS-бюджеты описаны в `RUNTIME.md` backend.

## Проверки

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm start
```

Те же проверки выполняются в GitHub Actions. Для проверки ролей используйте
отдельные аккаунты и изолированную базу. Браузерные сценарии должны подтверждать
сохранение после перезагрузки, ошибки API и запрет доступа к чужим данным.

## Границы реализации

Платёжный провайдер не подключён. GPS/телематика не подключены. Фоновый планировщик поставок необходимо отдельно
включить и настроить по backend RUNTIME.md; по умолчанию он отключён. Мониторинг показывает сохранённые статусы рейсов;
операционная аналитика считает рейсы, пассажиров, брони и обращения. Финансовая
отчётность не заявлена. Реальную отправку SMS необходимо проверить после настройки
аккаунта провайдера и отзыва старых ключей.

Автобусная компания регистрируется через `/admin/registration`: нужен отдельный
номер телефона, который ещё не используется в Jol, уникальный БИН / ИИН и пароль.
После проверки SMS создаётся кабинет владельца; существующие пассажирские аккаунты
не получают права перевозчика автоматически. Проверка SMS подтверждает владение
телефоном, а реквизиты компании указывает сам владелец.

Удаление аккаунта пассажира в этом выпуске не реализовано. Документы автобусов
доступны в `/admin/main/documents`: свидетельство регистрации, страховка и
техосмотр, срок действия, замена и удаление. Документы автобусов и Cargo доступны через
авторизованный proxy: PDF/JPEG/PNG до 10 МиБ, без публичных ссылок на хранилище.

Подробный отчёт об изменениях и границах проверки: [docs/NIGHT_REPORT.md](docs/NIGHT_REPORT.md).
